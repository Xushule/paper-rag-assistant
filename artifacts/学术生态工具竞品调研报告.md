# 学术生态 / 文献发现类工具竞品调研报告

> **调研目的**：为求职项目「论文阅读问答助手」（DeepSeek LLM + Ollama bge-m3 embedding + Chroma 向量库 + 自实现 BM25 + RRF 混合检索 + 引用溯源 [n]）做竞品借鉴调研。
> **调研范围**：仅覆盖"学术生态 / 文献发现"类工具——Connected Papers、Semantic Scholar（含 Semantic Reader / API）、Scite（必做），并补充 OpenAlex、Litmaps、ResearchRabbit（可选）。不覆盖通用 AI 助手、专业论文 SaaS、开源项目。
> **口径说明**：
> - 【已核验】= 官方文档 / 官网 / 大学图书馆评测 / 同行评议论文中可查，附来源 URL；
> - 【推断 / 宣传口径】= 官方未明确公开、或第三方二手转述，文中明确标注；
> - 调研时间：2026-10-08。

## 1. Connected Papers

### 1.1 核心定位
解决的是**"从一篇种子论文出发，快速看清一个研究领域的学术地形"**的问题：输入一篇论文（标题 / DOI / arXiv ID / 关键词），输出一张相关论文关系图谱，帮你在文献综述阶段一次性发现" intellectual neighborhood"，而不是逐篇翻引用列表。它**不解决**可信度判断、也不解决"某句话被谁怎么引用"的问题。【已核验：LMU 图书馆指南 https://librarynews.lmu.edu/2025/10/the-changing-landscape-of-academic-search-and-connected-papers/ ；CASRAI https://casrai.org/guides/connected-papers 】

### 1.2 核心功能与交互设计
- **相似度算法（公开口径）**：基于两个经典文献计量指标——
  - **共被引（co-citation）**：两篇论文经常被第三篇论文同时引用；
  - **文献耦合（bibliographic coupling）**：两篇论文引用了高度重叠的一组参考文献。
  - 满足任一即判定为"概念相近"，即使两篇论文彼此从未直接引用。【已核验：CASRAI https://casrai.org/guides/connected-papers ；Semantic Scholar 上的用户论文 https://pdfs.semanticscholar.org/1894/9e65d33b5f1065f226c940f2e5a950949878.pdf 】
- **图谱生成**：对每个领域约扫 50,000 篇论文，最终只展示与种子最相关的 **40–50 个节点**，用力导向图（force-directed graph）布局成簇。【已核验：LMU 图书馆 https://librarynews.lmu.edu/2025/10/the-changing-landscape-of-academic-search-and-connected-papers/ 】
- **视觉编码**：节点大小 = 被引量；节点颜色 = 发表时间（越新越深 / 越亮，按官方惯例）；连线粗细 = 相似度强度；可区分"先驱工作（Prior Works）"与"衍生工作（Derivative Works）"。【已核验：同上 LMU 图书馆；AI星图介绍 https://www.aistarmap.com/en-US/aitool/connected-papers 】
- **交互**：点击节点弹出该论文摘要、作者、年份、引用数；支持导出图谱数据 / 引用列表。【推断：导出功能为产品常规能力，具体导出格式未在本次官方文档精读中核实】
- **数据底座**：官方在 Semantic Scholar API  testimonial 中明确写道"Connected Papers has been built on top of the Semantic Scholar Open Corpus and APIs"。【已核验：https://www.semanticscholar.org/product/api 】
- **免费额度**：第三方评测称免费档约 5 张图/月。【推断 / 第三方口径：https://tesify.it/blog/researchrabbit-litmaps-connected-papers-tesi-2026 ，未在官网核实】

### 1.3 对个人项目的借鉴点
- **概念可借鉴、数据层不可借鉴**：它的"共被引 + 文献耦合"需要全量引用图数据，个人项目没有这个语料；但其思想可以在**小范围**复现——基于用户本地论文库（你已入库的论文），用 bge-m3 embedding 余弦相似度构建"相关论文小图谱"，作为一个加分可视化模块，而不是照搬全领域地图。
- **视觉编码约定可直接抄**：节点大小=引用数、颜色=年份、连线粗细=相似度——这是用户一眼就懂的编码方式，面试讲设计决策时很好用。
- **不值得做**：力导向图属于重前端工作（D3 / vis-network），与"论文问答 + 引用溯源"核心主线关系弱，建议作为简历项目的"可选扩展"而非必做。

### 1.4 技术实现线索（公开信息）
- 数据来自 Semantic Scholar 开放语料（ODC-BY）；相似度 = 共被引 + 文献耦合混合；渲染为力导向图。【已核验，见上】
- 具体权重、打分公式未公开。【推断：未公开】

### 1.5 可借鉴点清单
1. 相关推荐的"小图谱"交互范式（节点大小/颜色/连线编码约定）。
2. "Prior Works / Derivative Works"二分视角：向前看引用了谁、向后看谁引用了它——可在项目里做成两个按钮。
3. 不建议接入其任何 API（无公开开放 API，本身就是付费 SaaS）。

### 1.6 可借鉴程度评分
**低（对核心功能）/ 中（作为可选可视化加分项）**。理由：它的核心壁垒在"全领域引用图数据"，个人项目无法复制也无需复制；真正可拿的是交互范式和视觉编码，而非数据能力。

## 2. Semantic Scholar（含 Semantic Reader / API）

### 2.1 核心定位
AI2（Allen Institute for AI）做的**学术搜索 + 开放学术数据基础设施**。它一手做面向读者的搜索引擎与增强阅读器 Semantic Reader，一手把整个语料以 **免费 API / 开放数据集**形式开放给开发者——Connected Papers、Litmaps 都是它的数据下游。【已核验：https://www.semanticscholar.org/product/api （页面含 Litmaps、Connected Papers 官方 testimonial）】

### 2.2 核心功能与交互设计
**（a）学术搜索与排序**
- 不是纯关键词匹配：内置 AI 理解论文结构，有 **TLDR**（一句话 AI 摘要）、**Highly Influential Citations**（高影响力引用，区别于普通引用数）、引用类型过滤（cites background / methods / results）。【已核验：https://www.semanticscholar.org/product/tutorials 】
- 语料规模：**2.14 亿篇论文、24.9 亿条引用、7,900 万作者**。【已核验：https://www.semanticscholar.org/product/api 】

**（b）Semantic Reader（增强阅读，对本项目借鉴价值最高）**
这是一个"在 PDF 原文之上叠加 AI 层"的阅读器，核心增强（均为官网已核验）：
- **Citation Cards**：点击正文里的内联引用 [n]，**就在阅读位置原地弹出**被引论文的卡片（标题、作者、TLDR 摘要），不用翻到参考文献页、不用新开标签页。【已核验：https://www.semanticscholar.org/product/semantic-reader 】
- **个性化内联引用着色**：同一篇引用根据"是否在你的库里 / 是否被你库里论文引用过"着不同颜色（CiteSee 研究：已读=绿、已存=红、再遇引用=黄→橙渐变）。【已核验：官网产品页 https://www.semanticscholar.org/product/semantic-reader ；ACM CiteSee 论文 https://dl.acm.org/doi/fullHtml/10.1145/3544548.3580847 】
- **Scim 高亮**：自动识别关键句子并按修辞功能分三类高亮——**Goal / Method / Result**，用户可调高亮数量与透明度。【已核验：官网产品页；Scim 论文 arXiv:2205.05731（官网列出）】
- **ScholarPhi 按需释义**：带下划线的术语 / 符号，点一下弹出基于"当前论文上下文"的 AI 定义。【已核验：官网产品页】
- **CiteRead**：把"后续引用本文的论文如何讨论本文"的上下文嵌进阅读界面。【已核验：官网产品页列出 CiteRead (IUI 2022)】
- **开源底座**：PaperMage + PaperCraft 开源库（PDF 解析 + 阅读器构建），开放给社区自建阅读器。【已核验：https://openreader.semanticscholar.org/ 】

**（c）API 免费开放情况（本项目最关心，已逐条核实官方文档）**
| 项目 | 已核验数据 | 来源 |
|---|---|---|
| 免认证使用 | 大部分端点无需 key，但所有匿名用户共享一个 **1000 req/sec** 的池子，高峰会被进一步限流 | https://www.semanticscholar.org/product/api |
| 免费 API Key | 免费申请；**入门速率为全端点 1 req/second**；部分用户经审核可获更高额度 | https://www.semanticscholar.org/product/api ；教程页 https://www.semanticscholar.org/product/api/tutorial |
| 三大 API | ① Academic Graph（`api.semanticscholar.org/graph/v1`：论文/作者/引用/会议/**SPECTER2 embedding**）；② Recommendations（基于一篇论文推荐相似论文）；③ Datasets（整包下载） | https://www.semanticscholar.org/product/api ；教程页 |
| 引用数据字段 | citations 端点可返回 **citation context（引用上下文原句）+ citation intent（引用意图）+ influential 标记**；另有 `influentialCitationCount` 字段 | API 文档 https://api.semanticscholar.org/api-docs/ ；Semantic Scholar 开放数据平台论文 arXiv:2301.10140（"citations: Citation links between papers, with citation context and intent and influential classifications"） |
| Embedding | 官方提供 **SPECTER / SPECTER2** 论文 embedding（开放数据集中） | arXiv:2301.10140；官网 API 页（"SPECTER2 embeddings"） |

> 注意：网络上流传的"匿名 5000 req / 5 min"等数字来自其旧版 / 镜像文档，**以官网 1 RPS（带 key）+ 共享池（不带 key）为准**。【已核验口径来源同上】

### 2.3 对个人项目的借鉴点（最重要）
1. **直接接 Semantic Scholar API 做"元数据补全 + 相关论文推荐"（强烈推荐，面试加分项）**：
   - 用户导入一篇论文（有 DOI / arXiv ID / 标题）→ 调 `GET /graph/v1/paper/{id}` 补全标题、作者、年份、摘要、TLDR、引用数、高影响力引用数；
   - 调 **Recommendations API** 直接获得"相关论文列表"，零训练成本；
   - 1 RPS 对个人项目完全够用（元数据按需拉取 + 本地缓存即可），免费、无需付费。
2. **citation contexts 直接喂给你的"引用溯源 [n]"功能**：
   - 你的项目是"读论文问答，答案带 [n]"。Semantic Reader 的设计证明了：用户看到 [n] 时最想要的不是参考文献列表，而是**原地弹出卡片 + 被引处的原句上下文**。
   - 更进一步：Semantic Scholar API 的 citations 端点自带 `contexts`（引用原句）和 `intents`——如果你做"这篇论文被后续工作怎么评价"的功能，可以直接拉官方数据，而不是自己从 PDF 里抠。
3. **Semantic Reader 的交互可低成本复刻到你的问答界面**：
   - 回答里每个 `[n]` → 点击原地展开一张小卡片（论文标题 + TLDR + 你的 RAG 命中的原句片段）；
   - Scim 的 Goal/Method/Result 三类高亮 → 你可以让 DeepSeek 对检索到的段落打"目标/方法/结论"标签，辅助用户扫读。
4. **Embedding 路线对比**：官方 SPECTER2 是为"论文间相似度"训练的；你本地用 bge-m3 做"问题↔段落"检索。两者不冲突——面试时可以讲清楚分工：**bge-m3 负责 RAG 检索，S2 API 负责跨论文推荐**，这是有数据支撑的架构决策。

### 2.4 技术实现线索
- 开放数据平台论文（arXiv:2301.10140）公开了数据 schema：abstracts / authors / citations（含 context + intent + influential）/ embeddings(SPECTER) / paper-ids。【已核验】
- TLDR、Scim 高亮、ScholarPhi 均有对应 CHI/IUI 论文公开方法。【已核验：官网产品页列出全部论文】

### 2.5 可借鉴点清单
1. **接入 API**：元数据补全 + Recommendations 相关论文推荐 + citations 的 context/intent 字段（免费、1 RPS 够用）。
2. **抄交互**：内联引用卡片（点 [n] 原地展开）、Goal/Method/Result 高亮、按需术语释义。
3. **抄数据产品思维**：influential vs 普通引用的区分——你也可以在问答里区分"高置信引用（命中多段/语义相似度高）"与"弱相关引用"。

### 2.6 可借鉴程度评分
**高**。理由：(a) 官方 API 免费、文档齐全、1 RPS 对个人项目绰绰有余，能直接给项目加"相关论文推荐 + 元数据补全"两个现成能力；(b) Semantic Reader 的内联引用卡片设计与你的 [n] 引用溯源功能几乎是同构需求，是最直接的交互借鉴对象。

## 3. Scite（Smart Citations）

### 3.1 核心定位
解决的是**"一篇论文的观点到底被后续工作支持还是反驳了"**——即**可信度 / 引用语境判断**问题。传统引用计数把"支持你"和"反驳你"的引用算成同一个数；Scite 用 NLP 读每一处引用的上下文，把它分类成**支持（supporting）/ 反驳（contrasting）/ 提及（mentioning）**，并给出该引用出现的论文章节（如 Introduction / Results）。【已核验：Clemson 大学图书馆官方介绍 https://open.clemson.edu/cgi/viewcontent.cgi?article=1014&context=ctec ；JMLA 论文《SCITE: A Deep Learning Platform to Contextualize Citation Counts》https://www.jmla.mlanet.org/ojs/jmla/article/download/1331/1396 】

### 3.2 核心功能与交互设计
- **Citation Report（引用报告）**：每篇论文一个报告页，顶部是三个数字——Supporting / Contrasting / Mentioning 各多少条；点任一分类，列出**精确的引用原句（citation statement）**，并附该句出自哪篇论文、论文章节、分类置信度。【已核验：Syracuse 大学图书馆 https://library.syracuse.edu/blog/collection-spotlight-scite-ai/ ；Clemson 同上】
- **Smart Citation Badge（徽章）**：免费可嵌入的徽章组件，把三分类数字直接挂在出版社页面 / Google Scholar / PubMed 旁边；浏览器扩展在任何网页上看到论文就弹出这个 badge，可点开看引用原句。【已核验：Syracuse 图书馆；AI Wiki 词条 https://www.aiwiki.ai/wiki/scite_ai 】
- **数据规模**：Clemson 官方介绍称其收录 **超过 12 亿条引用陈述（citation statements）、1.85 亿篇全文**。【已核验：https://open.clemson.edu/cgi/viewcontent.cgi?article=1014&context=ctec 】（第三方另有 16 亿条的更新数字，属【推断/第三方口径】https://aitoolsatlas.ai/tools/scite-ai/pricing ）
- **延伸**：scite Assistant（基于全文的对话问答）、编辑通知/撤稿计数、参考文献自动检查。【已核验：JMLA 论文；Syracuse 图书馆】
- **技术口径**：官方称用深度学习模型阅读引用周围上下文做分类；模型细节未公开。【推断：模型未公开，属宣传口径】

### 3.3 对个人项目的借鉴点
1. **"引用态度三分类"的展示设计，可低成本用你自己的 LLM 复刻（强烈推荐）**：
   - Scite 的数据是付费专有的，个人项目接不了、也不必接；
   - 但它的**交互思想**可以直接迁移：你的 RAG 系统召回的证据段落，让 DeepSeek 多走一步——对每段证据标注它对"答案结论"是 **支持 / 反驳 / 仅提及**，并在 [n] 引用旁用绿/红/灰小标签显示。
   - 这在面试里是很好的故事："调研 Scite 后，我在 RAG 回答里加了证据态度标注，让用户一眼看出哪些段落是支撑结论、哪些是反例"——比单纯堆 [n] 引用更能体现"批判性引用溯源"。
2. **"引用原句 + 出处章节"的呈现**：Scite 证明用户要的是"精确那一句话"，不是摘要。这再次印证你的 [n] 溯源应直接展示**命中原文片段（带页码/章节）**，而不是整篇论文摘要。
3. **Badge 思维**：在项目首页/论文详情页挂一个"该论文被你的问答系统命中了 N 次、其中支持 X / 反驳 Y"的小统计——把 Scite 的三分类 badge 本地化。

### 3.4 技术实现线索
- 已核验的公开信息：从全文中抽取引用句 → NLP 分类为 supporting/contrasting/mentioning → 标注章节位置 → 附置信度。【已核验：JMLA 论文 + 大学图书馆介绍】
- 模型本体、训练数据、接口价格均未在本次免费资料中核实；其 API 存在但面向机构付费。【推断：不建议个人项目接 Scite API】

### 3.5 可借鉴点清单
1. **证据态度三分类标签**（支持/反驳/提及）——用 DeepSeek prompt 即可实现，不依赖 Scite 数据。
2. **引用必须落到"原句级"**，附章节/页码——强化你现有 [n] 溯源的颗粒度。
3. 不借鉴其数据 API（付费专有）；只借鉴其信息架构。

### 3.6 可借鉴程度评分
**中（可接入性）/ 高（设计借鉴）**。理由：Scite 的核心数据与 API 是付费专有，个人项目无法直接接入；但其"引用态度分类 + 原句级引用"是三个必做产品里**最容易用本地 LLM 复刻、且最能在面试中讲出差异化**的设计，设计借鉴价值高。

## 4. 可选产品补充

### 4.1 OpenAlex（重点：免费 API 第二数据源）
- **定位**：完全开放的学术目录图谱（works / authors / venues / institutions / concepts 互联），前身是 MAG，免费、无登录即可用。【已核验：https://help.openalex.org/api/ 】
- **API 免费额度（重要：2026 年 2 月改了计费模型，网上旧资料已过时）**：
  - 现行：**免费 API key = 每天 $1 免费额度；无 key = 每天 $0.10**；超出后按量付费。【已核验：https://developers.openalex.org/api-reference/authentication ；https://help.openalex.org/api/authentication/ 】
  - **速率上限**：无论预算多少，**超过 100 req/sec 直接 429**；日预算耗尽也 429。【已核验：https://help.openalex.org/api/authentication/ 】
  - 单次查询硬限制：`per_page` 最大 100；单个 filter 的 OR 值最多 100；基础翻页最多 10,000 条（深翻用 cursor paging）。【已核验：同上】
  - **旧的"polite pool（带 email 提额）"已于 2026 年 2 月废弃**，现在统一用免费 API key。【已核验：https://help.openalex.org/api/deprecations/ 】
  - 响应头自带 `X-RateLimit-Limit / Remaining / Credits-Used / Reset`，可监控用量。【已核验：同上】
- **对项目的借鉴**：
  1. 作为 Semantic Scholar 的**备胎/互补元数据源**——S2 拉不到时用 OpenAlex 按 DOI/标题补元数据；
  2. OpenAlex 的 `related_works` / `referenced_works` / 被引列表可做"向前/向后引文追踪"；
  3. 个人项目量级（每天几百次查询）在 $1/天免费额度内绰绰有余。
- **评分：高**（作为免费元数据 + 引文图第二数据源）。

### 4.2 Litmaps / ResearchRabbit（简要）
- **Litmaps**：多种子论文的可视化文献地图，数据来自 **OpenAlex + Semantic Scholar + Crossref**，覆盖 2.7 亿篇有 DOI 的论文；做"两度引文探索"。【已核验：Information Today 评测 https://www.infotoday.com/cilmag/oct24/Archambault-Rincon--An-Evaluation-of-Cutting-Edge-AI-Research-Tools-Using-the-REACT-Framework.shtml 】
- **ResearchRabbit**：以"Collection（文献夹）"为单位做迭代式雪球发现，支持作者网络可视化、Zotero 双向同步、新引用邮件提醒。【已核验：https://tesify.app/best-literature-mapping-tools-litmaps-connectedpapers-2026/ 】
- 【第三方口径】ResearchRabbit 于 2025 年被 Litmaps 收购（https://www.aiwiki.ai/wiki/researchrabbit ，未在官方一手来源核实）。
- **对项目的借鉴**：**低**。二者与 Connected Papers 同属"图谱发现"赛道，交互思想已被 Connected Papers 覆盖；区别（多种子、Collection 化、作者网络）对一个问答助手项目增益有限。

## 5. 学术生态类对个人项目的借鉴总结

### 5.1 可以直接接入的免费数据能力（已核验，面试可直接讲）
| 能力 | 推荐数据源 | 免费额度（已核验） | 用到项目哪里 |
|---|---|---|---|
| 论文元数据补全（标题/作者/年份/摘要/TLDR/引用数） | Semantic Scholar Academic Graph API | 带免费 key：1 req/sec；不带 key 共享 1000 req/sec 池 | 用户导入论文时自动补全卡片 |
| 相关论文推荐（零训练） | Semantic Scholar Recommendations API | 同上 | 论文详情页"相关阅读"模块 |
| 引用上下文原句 + 引用意图 | S2 citations 端点（`contexts` / `intents` / `influential` 字段） | 同上 | "这篇论文被后续工作怎么评价"面板 |
| 元数据备胎 + 前后引文追踪 | OpenAlex API | 免费 key：$1/天；无 key：$0.10/天；≤100 req/sec | S2 拉取失败时兜底 |

> 结论：**"相关论文推荐 + 元数据补全"完全可以用 Semantic Scholar / OpenAlex 免费 API 实现**，无需自己爬取；这在面试里是"会用开放数据生态"的硬证据。

### 5.2 可以直接抄的交互设计（按你的功能映射）
1. **你的 [n] 引用溯源 ← Semantic Reader 的 Citation Cards**：点 [n] 原地弹出卡片（标题 + TLDR + 命中原句），不跳转、不翻页。
2. **你的答案展示 ← Scite 的 Smart Citations**：对 RAG 召回的每段证据，让 DeepSeek 标注 **支持 / 反驳 / 提及**，用绿/红/灰小标签挂在 [n] 旁——做出"批判性引用"差异化。
3. **你的扫读辅助 ← Semantic Reader 的 Scim**：对长论文，用 LLM 标出 Goal / Method / Result 三类句子。
4. **你的相关阅读可视化 ← Connected Papers**：本地 bge-m3 embedding 在用户论文库内做小图谱（节点大小=引用数、颜色=年份），作为可选加分项。

### 5.3 不建议碰的
- Connected Papers / Litmaps / ResearchRabbit 的图谱本体（重前端 + 数据壁垒在官方侧，你接不到它们的数据）；
- Scite 的付费 API（专有机构服务，个人项目无免费额度）；
- 不要在简历里写"自研了类似 Connected Papers 的全领域引用网络"——那是 5 万篇论文级语料的工程，与你 RAG 主线无关，写了会被追问穿。

### 5.4 一句话给面试官的讲法
> "我没有重复造轮子去做文献发现：元数据和相关推荐直接接 Semantic Scholar 免费 API（1 RPS 足够个人项目），OpenAlex 做兜底；交互上借鉴了 Semantic Reader 的内联引用卡片和 Scite 的引用态度分类——用 DeepSeek 给每段证据打支持/反驳/提及标签，让引用溯源不只是'标出处'，而是'标证据立场'。"
