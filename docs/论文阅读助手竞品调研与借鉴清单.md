## 一、四类竞品总览盘点

### 1.1 通用 AI 助手（文件/论文问答）

| 产品 | 定位 | 引用溯源设计 | 对项目的借鉴度 |
|---|---|---|---|
| **NotebookLM** | 来源锁定的多文档问答 + 笔记 | **行内数字引用 → 悬停看原话引文 → 点击跳原文**（chunk 级）【已核验 support.google.com/notebooklm】 | **高**（交互标杆） |
| **Claude** | 长上下文 + Projects | **API 级引用坐标**：句子级切分 + `(页码区间/字符区间, cited_text)` 三坐标【已核验 docs.anthropic.com Citations】 | **高**（工程蓝本） |
| **ChatGPT** | 附件 + Projects/Library | 附件问答**无原生行内角标、页码会丢**【二手报道，无确证】 | 低（反面教材） |
| **豆包** | 附件/网页问答 | 未见系统 chunk 级锚点【推断】 | 低 |
| **Kimi** | 长文档（~20 万字） | 长上下文直答，无 chunk 锚点【推断】；有 Context Caching【已核验】 | 低–中 |
| **通义千问** | 文件问答 + 企业版 | 企业版有 Reference localization（来源文件页/段）【已核验】；媒体实测"关键数据可溯源到页码"【二手】 | 中 |

**两类路线分野（面试直接可讲）**：
- **长上下文吞文档**（ChatGPT/Kimi/通义/豆包）：省事但丢页码丢锚点，无法做引用溯源；
- **RAG + chunk 级溯源**（NotebookLM/Claude API）：行内角标、悬停看原话、点击跳原文。

你的项目属第二类 —— 这本身就是差异化。

## 二、别人是怎么设计的（五主题提炼）

### 2.1 引用溯源设计 —— 全行业最有共识、也最值得抄的部分

| 方案 | 代表产品 | 具体做法 |
|---|---|---|
| 行内数字角标 + 悬停看原话 + 点击跳原文高亮 | NotebookLM、SciSpace Anchored、ChatPDF、Zotero 插件 | `[n]` 不是装饰：悬停弹**引文原句**，点击右侧 PDF **滚动+高亮** |
| 引用坐标存元数据 | Claude API（工程层标杆） | 句子级 chunk，存 `(doc_id, page, start_char, end_char, cited_text)`，引用就近挂在主张后 |
| 生成式 key + 后处理映射 | paper-qa（后端机制标杆） | chunk 入库分配 `pqac-<hash>`，prompt 教 LLM 插 `(pqac-xxx)`，生成后正则提取映射回原文 → 你的 [n] 就是它 |
| 生成式 [n] + posthoc 校验 | OpenScholar | 生成后**多一次 LLM 调用**："每个需引用的论断是否都挂了 [n]，缺了补插"；500 token 成本 |
| 页码双索引 | ChatPDF / Zotero | `[3, p.7 ¶2]` 双索引角标 + PDF.js 联动 |
| 点击原地弹卡片 | Semantic Reader | [n] 点击原地展开被引论文卡片（标题+TLDR+命中原句），不跳页 |
| 证据表 + 立场分布 | Elicit / Consensus / Scite | Elicit：行=论文、列=字段、每格带引用；Consensus Meter：百分比堆叠条（73% 支持…）；Scite：支持/反驳/提及 三分类徽章 |
| 每句挂引用（抽取式兜底） | Paper Digest | 摘要中每个句子可溯源到原文句子 |

**关键结论**：引用溯源做得好的产品都是"**角标 → 原话 → 原文位置**"三层打通，且**引用必须落在 chunk/句子级而不是整篇级**。你已有 [n]，缺的是：原话冗余存储（供悬停）、点击跳原文的坐标、以及生成后的引用自检。

### 2.2 检索与重排架构

| 方案 | 代表 | 做法 |
|---|---|---|
| 混合检索 + RRF | RAGFlow、FastGPT、你的项目 | dense + BM25（+full-text）→ RRF 融合。你的实现与生产级项目同构 |
| 两阶段 dense → cross-encoder rerank | QAnything、OpenScholar | bge-reranker 对 top-N 精排；**消融显示去掉 rerank 正确性掉 5–20 分**【已核验 OpenScholar 论文】 |
| 质量信号加权 | OpenScholar / Consensus | 相关性分数 + 年份/被引数/期刊影响因子；OpenScholar 用 `max_per_paper=3` 防单篇垄断 |
| LLM contextual summary 重排（备选） | paper-qa | 不跑 reranker 模型，让 LLM 给每个候选 chunk 写"结合 query 的摘要"再挑 |
| 多轮 query 拼接 | FastGPT | 追问时把上一轮 query 拼进检索 query（**你的多轮记忆已实现此思路**） |

**对你（bge-m3 + BM25 + RRF 已就位）的差距**：只差 **Rerank 一环**（技术选型表已选 bge-reranker-v2-m3），以及可选的质量信号加权 / max_per_paper 去重。

### 2.3 Agent / 多步检索设计

| 方案 | 代表 | 做法 | 对你的价值 |
|---|---|---|---|
| self-feedback loop | OpenScholar | 生成 y0 → LLM 给 ≤3 条自然语言反馈 → 缺信息则自动补检索 query → 迭代到 yT；消融掉 feedback 正确性 -26 分 | M3+ 面试亮点，工程量大 |
| 工具编排 Agent | paper-qa v5 | SearchPapers / GatherEvidence / GenerateAnswer 三工具，任意顺序调用（也有硬编码路径省 token） | 复杂度高，个人项目可只讲故事 |
| 两阶段固定 pipeline | QAnything、ChatPaper | 检索 → 生成，固定顺序 | 你的现状（正确） |
| Agentic Retrieval | RAGFlow v0.27 | 检索 agent 化 | 了解即可 |

**结论**：自反馈 / Agent 化对个人项目偏重，**先不做**；Rerank + 引用自检是"性价比最高的两笔投入"。

### 明确不值得做（面试会被追问穿的部分）

- ❌ 2.8 亿论文库检索 / 全领域引用图谱（Connected Papers 式）——数据基建护城河，个人项目复制不了
- ❌ Scite 付费 API（数据接不了）、KAG 知识图谱（建图成本过高）
- ❌ GPT-Academic / ChatPaper 的"PDF 全文直喂 LLM"路线——无引用、无检索，与你的差异化相悖
- ❌ PRISMA 系统综述流程图（Elicit 重度场景）、Audio Overview 播客类花活

## 五、求职面试：亮点与叙事

### 一句话定位（README 开场）

> **"NotebookLM 的引用溯源交互 + Claude 的 chunk 坐标工程 + 自研 BM25/RRF 混合检索 + 本地优先（Ollama + DeepSeek）"** —— 装在自己电脑上的私人论文阅读与写作助手。

### 面试三句话（写进 README / 简历项目描述）

1. **"无引用不回答"** —— 对标 Consensus Responsible AI、Paper Digest 每句挂引用；检索不到明确说明，不编造。带评测数据（幻觉率、MRR）。
2. **"混合检索 + Rerank + 引用自检"** —— 自实现 BM25 + bge-m3 RRF 融合（SaaS 不暴露这种细节）；Rerank 消融有量化对比；生成后 LLM 校验引用（对标 OpenScholar posthoc attribution）。
3. **"本地优先，数据不出本机"** —— Ollama 本地 embedding + DeepSeek API；对标 Zotero 插件生态 BYO Key 已验证的路线，但是独立 Web 应用。

### 放进简历项目描述的能力点（按面试价值排序）

| 能力点 | 面试能讲什么 |
|---|---|
| 混合检索 RRF + Rerank 消融对比 | 检索工程化的标准做法 + 量化实验（MRR/正确性前后对比） |
| 引用溯源三层链路（key→原话→坐标→自检） | 对比 NotebookLM/paper-qa 的实现方案，讲清"为什么不用长上下文塞全文" |
| 结构感知分块 + 论文作用域 | PDF 解析踩坑（双栏/丢空格/标题误判）+ 防多论文串台的设计 |
| 免费开放数据 API 接入 | "没重复造轮子"：S2/OpenAlex 做元数据补全与相关推荐 |
| 中英术语查询改写 + 多轮记忆 | 中文问英文论文的实际问题 + 省略指代落空问题的解法 |

### 面试易被追问的三个点（提前准备）

1. **"为什么不用 LangChain/RAGFlow，要自己写？"** —— 自研分块/检索细节可讲原理、面试有深度；生产级框架作为对比参照（能说出各自架构即可）。
2. **"引用会不会漂移（数字看着对、段落不支撑）？"** —— 答：Rerank 重排 + 引用自检 + 存原话冗余供校验，三层缓解（对标 NotebookLM 已知的引用漂移风险）。
3. **"40 篇论文 scale 上去行不行？"** —— 答：当前 Chroma 单机足够；讲清换 Milvus/加 rerank 的扩展路径（技术选型表已备）。
